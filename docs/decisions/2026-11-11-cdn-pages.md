# Serve prerendered pages from the CDN

**Date:** 2026-11-11 · **Status:** accepted

## Context

Each page request ran the Vercel Function ([2026-11-04-app-server.md](./2026-11-04-app-server.md)), also for a page that is the same for each visitor. `@ngrok/app-server` 0.3.3 added `vercel({ cdnPages: true })`. The build sends each prerendered path through the pipeline two times, with two different clients. The CDN serves each page whose answer is the same for both, with the same headers.

## Decision

Set `cdnPages: true` in `vite.config.ts`. No page here reads a cookie, a query, or the host, so each one qualifies. The build log shows that the CDN serves 18 of 18 prerendered paths.

## Consequences

- A page view does not call the function. The function runs for a markdown twin, a 404, a redirect, and the GitHub squares route.
- A page that the CDN serves writes no access log line.
- The build log names each path that the function serves, with the reason. Read it after a change to `server.ts` or to a page: a plugin that varies on the visitor moves its pages back to the function.
- The CDN routes count toward Vercel's limit of 2,048 routes for each deployment. A post with a twin uses two.
